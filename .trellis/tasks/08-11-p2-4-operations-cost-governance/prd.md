# P2-4 运维和成本治理

## Goal

建立能定位线上问题、衡量模型成本、监控关键依赖并安全发布回滚的运行体系，使平台具备可运营性而不是只具备业务功能。

## Child Tasks

1. **P2-4A 可观测性与全链路追踪**：统一结构化事件和 trace/request/job 关联。
2. **P2-4B 模型使用与成本治理**：token、费用、归集、预算和异常用量。
3. **P2-4C 健康检查、告警与性能**：依赖健康、慢查询、作业失败和告警。
4. **P2-4D 部署与运维加固**：生产校验、备份恢复、发布回滚和运行手册。

## Dependency Order

P2-4A 在 P2-1A 稳定后启动；P2-4B 依赖 P2-2B；P2-4C 依赖 P2-4A；P2-4D 是 P2 最终收口任务。

## Acceptance Criteria

* [ ] 可按 traceId 关联请求、用户/tenant、数据批次、模型调用、报告和后台任务，且日志不泄露秘密或业务明细。
* [ ] 模型用量可按用户、tenant 和场景统计并发现异常。
* [ ] readiness 能区分应用存活与关键依赖不可用，告警可指向可执行的运行手册。
* [ ] 迁移、备份恢复、发布和回滚有自动检查与演练记录。

## Out of Scope

* 监控 SaaS、日志平台和告警渠道在实现任务中选择，本父任务不预设供应商。
* 不把可观测性作为记录明文 prompt、token、密码或完整业务数据的理由。
