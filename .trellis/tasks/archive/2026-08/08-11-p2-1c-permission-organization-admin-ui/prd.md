# P2-1C 权限与组织管理界面

## Goal

基于 P2-1A/P2-1B 的管理 API，为管理员提供用户、角色、组织、数据范围和会话管理界面，同时让普通用户只看到被授权的产品入口。

## Dependencies

* 前置：P2-1A 用户/角色/会话 API 与 P2-1B 组织/grant API、错误契约和 OpenAPI 稳定。
* 后续：P2-2 tenant 管理入口、P2-3 订阅协作管理。

## Requirements

* 集中维护当前用户、角色、权限和组织范围状态，页面刷新可恢复会话。
* 提供用户列表/创建/启停/临时密码重置/角色分配/会话撤销界面。
* 提供角色权限矩阵、组织树、经销商映射和用户/角色范围 grant 界面。
* 临时密码只在成功响应中展示一次；危险操作有确认、处理中状态和可理解错误。
* Dashboard、Chat、知识、报告和模型测试入口按权限隐藏或禁用，但所有提交仍由后端重新授权。
* 管理页面具备 loading、empty、error、冲突和无权限状态，并支持基础审计记录查看。

## Acceptance Criteria

* [ ] ADMIN 能完成用户、角色、组织和 grant 的核心流程，普通角色无法进入或调用管理 API。
* [ ] 最后管理员保护、版本冲突、禁用当前用户和会话撤销在 UI 中正确呈现。
* [ ] 临时密码不写入日志、本地存储或错误遥测。
* [ ] 组件、composable/API、权限路由和后端拒绝均有回归。
* [ ] 前端 lint/test/build 与后端相关回归通过。

## Implementation Plan

1. 管理 API client、认证状态与权限守卫。
2. 用户/会话和角色权限界面。
3. 组织树、映射和 grant 界面。
4. 审计视图、无权限/冲突体验和端到端回归。

## Out of Scope

* 不做 SSO、邮件找回密码或 service account 管理。
* 不做通用低代码权限设计器。
* tenant 管理能力在 P2-2 确定后扩展。
