# P2-1B 组织树与数据范围

## Goal

在 P2-1A 真实身份和功能权限之上增加集团、区域、城市、经销商/门店层级，使所有数据读取和 Agent 能力只能访问当前用户被授权的组织范围。

## Dependencies

* 前置：P2-1A 登录、当前用户、数据库实时权限和业务 API 授权已经收敛。
* 后续：P2-1C 管理界面、P2-2 tenant 所有权、组织级报告和订阅。

## Requirements

* 建立稳定组织节点、父子层级、节点类型、启用状态和经销商映射；禁止环和跨根挂载。
* 用户或角色可获得一个或多个组织 grant，并显式记录是否包含后代节点。
* 增加固定组织权限键，管理 API 只能组合代码认识的权限。
* 由单一授权上下文解析 principal、功能权限、组织节点和允许的 dealer 集合；客户端不得传入可信 scope。
* Dashboard、数据明细、规则分析、Chat/SSE、Agent tools、知识查询、报告生成/读取均在服务入口强制范围过滤。
* 授权或组织映射变更后，下一次请求读取数据库最新状态；写入安全审计。
* 现有 GLOBAL 数据通过明确迁移/初始化策略进入根组织，不静默扩大已有用户范围。

## Acceptance Criteria

* [x] 同集团不同区域、同区域不同门店以及多 grant 合并均有允许/拒绝测试。
* [x] `includeDescendants=false` 不会访问子节点；组织环、未知节点和禁用节点稳定拒绝。
* [x] HTTP、SSE、Agent、知识和报告对同一授权上下文给出一致范围。
* [x] 前端伪造 dealer/org 参数不能扩大范围。
* [x] H2 与 PostgreSQL Flyway/映射验证、PMD、后端和相关前端测试全部通过。

## Implementation Plan

1. 组织与 grant schema、领域约束和迁移测试。
2. 组织管理/映射 API 与统一授权上下文。
3. 各业务模块范围过滤和 Agent 二次校验。
4. 跨层拒绝矩阵、OpenAPI、配置和迁移说明。

## Out of Scope

* tenant 隔离与跨 tenant 所有权属于 P2-2。
* 图形化管理界面属于 P2-1C。
* 不实现跨组织数据共享审批或临时委托。
