# 测试验收方案

## 目标

建立从 POC 到真实项目重构过程中的质量门槛。测试不仅验证代码能运行，还要验证业务口径、数据质量、SSE 协议、前端体验和准确率题库不被破坏。

## 当前自动化基础

| 层 | 当前命令 | 覆盖 |
| --- | --- | --- |
| 前端 lint | `cd frontend && npm run lint` | JavaScript/Vue 静态检查 |
| 前端测试 | `cd frontend && npm run test` | 组件、composables、API、utils |
| 前端构建 | `cd frontend && npm run build` | Vite 构建到后端 static |
| 后端 PMD | `cd backend && mvn "-Dfrontend.skip=true" pmd:check` | Java 静态质量 |
| 后端测试 | `cd backend && mvn "-Dfrontend.skip=true" test` | Controller、Service、AI、导入、指标 |
| 后端完整构建 | `cd backend && mvn "-Dfrontend.skip=true" clean install` | 后端打包 |
| 联合构建 | `cd backend && mvn clean install` | 后端构建时执行前端 npm ci/build |

## 当前题库

准确率题库位于 `mockservice/DealerAIAssistant_准确率测试题库.xlsx`：

| Sheet | 用途 |
| --- | --- |
| `测试题库` | 类别、问题、标准答案、关键命中点/评分参考 |
| `评分模板` | 人工打分说明 |

题库应继续用于验证规则引擎 fallback 路径，尤其是未配置外部模型时的可复现回答。

## 测试分层

| 层级 | 目标 | 示例 |
| --- | --- | --- |
| 单元测试 | 验证纯函数、计算、解析、状态转换 | Markdown、SSE parser、AnalyticsCalculator |
| 组件测试 | 验证 UI 状态、事件、可访问性 | ChatInput、AssistantMessage、ModelSettingsPanel |
| API 测试 | 验证请求构造、鉴权头、错误处理 | frontend `api/*`、backend controller |
| 服务测试 | 验证规则、数据查询、导入、模型配置 | ChatService、RuleBasedAnalyticsService、ExcelImportService |
| 契约测试 | 验证 API/SSE 字段和顺序 | `analysis_metadata`、`step`、分页响应 |
| 题库回归 | 验证自然语言问题的命中点 | AccuracyWorkbookRegressionTest |
| 人工验收 | 验证真实交互体验 | 登录、提问、图表、错误恢复 |

## 重构质量门槛

### 前端改造

必须运行：

```bash
cd frontend
npm run lint
npm run test
```

涉及构建输出、静态资源、图表或样式时增加：

```bash
npm run build
```

验收重点：

* 新文案都有 zh/en。
* 新组件有 co-located test。
* 新请求走 `api/client.js` 或专用 SSE API。
* loading、empty、error、cancelled 状态可见。
* 图表/Markdown 失败有降级。

### 后端改造

必须运行：

```bash
cd backend
mvn "-Dfrontend.skip=true" pmd:check
mvn "-Dfrontend.skip=true" test
```

涉及前端打包或后端 static 输出时增加：

```bash
mvn clean install
```

验收重点：

* API 响应和错误语义稳定。
* 数据缺失值不被伪造。
* 指标 API 和聊天回答口径一致。
* 模型失败时规则路径可恢复。
* 安全配置不泄露真实密钥。

### 数据改造

必须覆盖：

* Excel 导入成功和失败。
* fallback enabled/disabled。
* 缺失必填字段跳过。
* 可选字段保留 `null`。
* 目标/活动可比样本口径。
* 数据状态接口。

### 联调改造

必须覆盖：

* 登录成功/失败。
* 数据状态展示。
* SSE 正常完成。
* SSE 错误恢复。
* 模型连接成功/失败。
* CORS 和 Vite proxy。

## 人工验收清单

| 场景 | 验收 |
| --- | --- |
| 初次打开 | 显示登录页，不泄露内部配置 |
| 登录 | 正确密钥进入聊天页，错误密钥提示错误 |
| 数据状态 | 样例回退时用户能看到警告 |
| 目标达成问题 | 返回结论、数据支撑、口径、限制和追问 |
| 商机漏斗问题 | 图表或表格可读，阶段口径明确 |
| 销售跟进问题 | 逾期/积压口径清楚 |
| 活动效果问题 | 目标和实际样本区分清楚 |
| 线索来源问题 | 来源和转化率口径清楚 |
| 门店对标问题 | 排名、差异和样本限制可见 |
| 清空会话 | 前后端会话状态同步清理 |
| 模型配置失败 | 失败原因可见，不破坏规则分析路径 |

## 待拆任务

| 优先级 | 任务 | 验收 |
| --- | --- | --- |
| P0 | 确认重构默认测试命令 | 每类改造都有最小命令集合 |
| P0 | 梳理准确率题库评分规则 | 标准答案和命中点可执行 |

| P1 | 增加跨层 smoke test | 登录、数据状态、聊天流可自动验证 |
| P1 | 数据导入质量回归 | 每类导入异常都有测试 |
| P1 | 人工验收模板 | 每次重构后可按表勾选 |
| P2 | CI 分层优化 | 快速 PR 门禁和完整 nightly 门禁分开 |

## 暂不做

* 不在本阶段引入 E2E 框架。
* 不默认把外部模型回答纳入严格准确率自动评分。
* 不用人工验收替代自动化回归。
