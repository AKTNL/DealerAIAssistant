# 重构总览

## 目标

将经销商 AI 分析助手从可演示的 POC 逐步整理为更接近真实项目的工程形态。第一阶段重点不是立刻替换所有代码，而是建立清晰的需求、边界、数据口径、接口契约、联调流程和验收门槛。

## 当前项目定位

当前项目已经具备可运行的端到端 POC：

* Vue 3 + Vite 单页前端。
* Spring Boot 3.4 + Java 21 后端。
* H2 内存数据库和 Excel 启动导入。
* 访问密钥登录和 session token。
* REST 数据查询、指标/详情 API。
* `POST /api/chat/stream` SSE 流式聊天。
* 规则分析引擎生成可复现分析，外部模型可做事实锚点上的润色。
* 前端渲染 Markdown、HTML 表格、ECharts/Mermaid 图表、分析元数据和思考步骤。
* 准确率题库用于验证规则引擎回答。

这些能力说明 POC 已经不是空壳，但它仍有明显 POC 特征：内存数据库、Excel 样例数据、弱账号体系、有限部署配置、缺少真实数据接入、缺少迁移和运维方案。

## 最新优先级

后续升级以 `07-生产化升级路线图.md` 和 `08-MVP产品需求文档.md` 为当前优先级来源。P0 已从“完整生产化底座”收敛为“先做 MVP”：优先用可复现的模拟业务数据、Dashboard 首版、最小业务/KPI 口径和现有分析链路验证用户价值。持久化数据库、完整架构模块化、Agent、RAG、自动报告和完整权限放到 MVP 之后分阶段推进。

## 重构原则

1. 先稳定数据口径，再扩展 AI 能力。
2. 先明确接口契约，再优化页面体验。
3. 先保留可复现规则路径，再引入更开放的模型推理。
4. 先保证本地和测试环境可联调，再谈生产部署。
5. 每一轮改造都要能被自动化测试或人工验收清单验证。

## 建议阶段

### 阶段 1：文档与边界

* 建立本批文档。
* 明确保留哪些 POC 能力。
* 标出每个主题的待拆任务和开放问题。

### 阶段 2：数据与后端基线

* 先固定真实数据模型和缺失值口径。
* 引入持久化和迁移策略的设计。
* 梳理 API 契约、错误响应和安全边界。

### 阶段 3：前端体验与联调

* 重构工作台状态和错误恢复。
* 明确 SSE 事件消费和降级行为。
* 建立可重复的本地/测试环境联调手册。

### 阶段 4：测试与验收

* 把准确率题库变成稳定回归门槛。
* 补充契约测试和关键链路测试。
* 建立人工验收清单。

## 暂不做

* 本阶段不重写所有源码。
* 本阶段不承诺真实生产部署。
* 本阶段不引入新的技术栈，除非某个后续任务明确决策。
* 本阶段不把 Word 需求基线全文转换为 Markdown。

## 开放问题

* 真实项目的目标用户是单店运营、区域经理、集团运营，还是多角色混合？
* 真实数据源来自 CRM、DMS、CDP、报表导出，还是仍先从 Excel 过渡？
* 外部模型服务是企业统一网关，还是用户可配置兼容 OpenAI endpoint？
* 是否需要多租户、门店权限隔离和审计日志？
