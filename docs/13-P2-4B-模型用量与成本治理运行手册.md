# P2-4B 模型用量与成本治理运行手册

## 1. 适用范围

本手册覆盖聊天、Agent、知识问答和模型连接测试的调用归集、token 与目录成本估算、价格版本、月度预算、provider 账单对账和回滚。当前报告与后台订阅使用确定性渲染，不产生虚假的模型事件；相关场景枚举只作为后续接入点。

成本治理是运营护栏，不是财务结算系统。`estimatedCost` 只表示调用发生时按 tenant 价格目录计算的估算值，不能替代 provider 发票、税费、折扣、缓存计费或批量价格。

## 2. 安全与权限

| 权限 | 范围 |
| --- | --- |
| `MODEL_USAGE_READ` | 当前认证主体所在 tenant 的汇总、事件、价格与预算 |
| `MODEL_USAGE_MANAGE` | 当前 tenant 追加价格版本、保存预算策略 |
| `MODEL_USAGE_PLATFORM_READ` | 仅在稳定默认平台 tenant（`tenantId=1`）读取跨 tenant 汇总 |

tenant ID 只从 `AuthPrincipal` 派生；管理 API 不接受 tenant ID 查询参数。平台汇总每次读取都会写 `PLATFORM_MODEL_USAGE_READ` 安全审计。

事件仅保存 tenant/user 内部 ID、provider/model、场景、状态、token、耗时、traceId、缓存标志和价格快照。禁止保存 prompt、completion、API key、Base URL、工具参数、请求/响应 body 或 provider-native metadata。

## 3. 归集语义

* Spring AI transport retry 位于 tracker 内层，因此一次逻辑 provider 调用只形成一条事件。
* Agent 多轮模型循环是多次真实 provider 调用，每轮分别形成事件。
* 流式响应保留最新/最大累计 token，不把每个 chunk 的累计值相加。
* 完成、错误和取消通过一次性结算保护只写一条事件；`callKey` 在数据库中唯一。
* token 字段全部缺失为 `UNKNOWN`，部分存在为 `PARTIAL`；不按 prompt 字符数推测。
* 用量持久化失败不会覆盖已成功的模型响应。硬预算预留未正常关闭时会在 10 分钟后过期回收。

调用写入同时产生 `agentpoc.model.usage.record` observation，metric 仍只使用低基数 `app.component` 与 `app.outcome` tag；tenant/user/call ID 只用于 trace 关联。

## 4. 价格目录上线

1. 从 provider 官方价格页或合同确认 provider、精确模型名、币种、每百万输入/输出 token 价格和生效时间。
2. 使用管理台“模型用量”页或 `POST /api/admin/model-usage/prices` 追加版本。
3. 发送一次受控模型请求，确认新事件的 `priceVersionKey`、单价快照、币种和 `estimatedCost`。
4. 价格变更时追加新版本，不更新或删除旧版本。历史事件保留当时的版本键与单价，不随目录变更重算。

同一 tenant 下 provider/model 匹配不区分大小写，取调用发生时 `effectiveFrom` 不晚于当前时间的最新版本。模型别名、日期或币种配置错误时应新增纠正版本；不要改写历史事件。

## 5. 预算上线顺序

预算按 UTC 自然月和单一币种计算。

1. **观察**：先保持预算未配置或仅使用软预算，至少收集一个代表性周期。
2. **补齐价格**：处理 `COST_INCOMPLETE` 和未知成本调用，确认主要模型都有有效价格。
3. **设置软阈值**：配置 `monthlyLimit`、`softThresholdPercent` 和币种；软阈值只改变状态，不拒绝调用。
4. **校准预留**：按历史高分位单次成本设置 `reservationAmount`，需覆盖常见高成本调用但不应等于整月预算。
5. **可选硬限制**：确认业务接受拒绝语义后再启用 `hardLimitEnabled`。默认关闭。

硬限制在同一 tenant 预算策略上使用数据库悲观锁。放行条件为：本月已知成本 + 活跃预留 + 本次预留不超过月度上限。实际调用成本可能高于固定预留，因此这是并发护栏，不是绝对财务保证。

`failOpen=true` 时治理存储故障放行模型调用；`failOpen=false` 时已加载的硬预算策略无法完成准入会拒绝。为保持首版模型可用性，完全无法读取治理状态时仍按 fail-open 处理。

## 6. 日常检查

管理台按时间范围检查：

* 总调用、输入/输出 token、错误、预算拒绝和未知 token 调用。
* 按场景与模型的调用/成本分布。
* `TOKEN_UNKNOWN`、`CALL_FAILED`、`BUDGET_REJECTED` 和高成本事件。
* 月度 `state`：`OK`、`COST_INCOMPLETE`、`SOFT_THRESHOLD` 或 `LIMIT_REACHED`。

通过事件 `traceId` 关联 trace 和结构化日志。排障时仍不得临时开启 prompt、completion、API key 或 payload 日志。

## 7. Provider 账单对账

1. 使用相同 UTC 时间窗口、provider、模型和币种导出 provider 用量/账单。
2. 分别比较调用次数、输入 token、输出 token 和费用，不只比较总金额。
3. 单列未知 token、无价格、失败、取消、缓存和 provider retry 差异。
4. 记录合同折扣、缓存价格、批量价格、舍入和税费等外部差异。
5. 需要纠正目录时追加价格版本。不要用 provider 账单回写或覆盖历史 `model_usage_events`。

首版不自动抓取 provider 账单，也不将差异静默改写为“实际费用”。

## 8. 故障处理

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 成本大量未知 | `tokenState`、price provider/model/effectiveFrom | 修正模型价格目录；provider 不返回 token 时保留未知 |
| 突然出现预算拒绝 | 月度已知成本、活跃预留、预留金额 | 核对币种与预算；必要时先关闭硬限制 |
| 用量事件缺失但模型成功 | `agentpoc.model.usage.record` error、数据库连接 | 恢复治理存储；不要重放真实 prompt 来补历史 |
| 活跃预留暂时偏高 | 调用是否仍在执行、预留 `expiresAt` | 等待正常关闭或 10 分钟过期，不手工删除在途预留 |
| 平台汇总 403 | 权限与当前 tenant | 切换到默认平台 tenant，并确认独立平台权限 |

## 9. 回滚

1. 立即调用 `PUT /api/admin/model-usage/budget`，将 `hardLimitEnabled=false`，保留月度限额和软阈值。
2. 如价格配置错误，追加从当前时间生效的纠正版本；不要删除旧版本或改写历史事件。
3. 治理写入故障时先恢复数据库。记录失败本身不会替换已成功的模型响应。
4. 不回滚或删除 Flyway V12 表，不清空事件、价格或审计记录。结构保留不影响模型调用。
5. 回滚后用受控请求验证模型调用恢复、事件结算一次、预算状态可读，并记录操作 traceId。
