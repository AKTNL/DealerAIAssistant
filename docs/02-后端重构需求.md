# 后端重构需求

## 目标

把当前支撑 POC 演示的 Spring Boot 后端整理为可持续扩展的业务分析服务。重点是明确 API 契约、服务边界、数据口径、AI/规则链路、安全配置和生产化缺口。

## 当前状态

| 主题 | 当前实现 |
| --- | --- |
| 技术栈 | Java 21、Spring Boot 3.4、Spring AI 1.0、Spring Web MVC |
| 数据访问 | Spring Data JPA + H2 内存数据库 |
| 数据导入 | `ExcelImportService` 启动导入 Excel，可在 demo 模式回退到内置样例 |
| API 风格 | REST + SSE |
| 认证 | 访问密钥换取 session token |
| 内部保护 | 部分数据 API 使用 `X-API-Key` |
| AI 链路 | 规则分析引擎优先，可选外部模型润色 |
| 质量 | JUnit、Spring Boot Test、PMD |

## 当前服务边界

| 模块 | 当前职责 | 重构关注点 |
| --- | --- | --- |
| `ChatService` | 聊天主流程、规则/模型分流、SSE 回调 | 体量和职责过大，需要拆分编排、上下文、输出保护 |
| `RuleBasedAnalyticsService` | 规则分析和 fallback 报告 | 业务规则、计算、文本生成需要分层 |
| `DashboardService` | Dashboard 汇总、active batch 聚合、数据状态摘要 | 后续应复用统一 KPI definition，支持筛选、趋势和下钻 |
| `AnalyticsApiService` | 指标聚合和详情分页 | API 口径与分析口径要保持一致 |
| `DataQueryService` | 原始数据过滤查询 | 参数校验、字段白名单、分页策略需要明确 |
| `ExcelImportService` | Excel 导入和清洗 | 真实数据接入后应拆成导入、校验、映射、质量报告 |
| `SessionMemoryService` | 后端会话记忆 | 真实项目需要持久化、租户隔离、过期清理 |
| `PromptFactory` | 系统提示词和输出约束 | 提示词版本、模板治理、审计需要明确 |
| `ChatReplyGuard` | 模型回答守卫 | 需要保留证据优先策略并增加可测试规则 |

## 生产化目标

### API 与契约

* 统一响应结构、错误码和分页参数。
* 明确哪些接口需要 session token，哪些需要内部 API key。
* SSE 事件类型、字段、顺序和错误行为要文档化并测试。
* OpenAPI 需要与代码保持同步。

### 服务分层

* Controller 只负责请求/响应，不承载业务逻辑。
* Service 拆分为编排、数据查询、指标计算、报告生成、模型调用、输出保护。
* AI 工具层和规则分析层共享同一套数据口径。
* 提示词和规则输出需要版本化或至少可追踪。

### 安全与配置

* 当前访问密钥适合 POC，不等同于生产账号体系。
* `APP_SESSION_SECRET`、`APP_API_KEY`、模型 API Key 必须从环境注入，不提交真实值。
* `APP_MODEL_ALLOWED_HOSTS` 和 `allow-private-hosts` 是模型服务安全边界。
* 生产配置目前只关闭 H2 Console 和 Excel fallback，还远不足以投产。

### AI 与规则链路

* 规则引擎结果是事实锚点，外部模型只能润色或解释，不应改写 KPI。
* 模型输出必须保留数据来源、限制和置信度。
* out-of-scope 问题需要稳定拒答，不应进入业务分析链路。

## 待拆任务

| 优先级 | 任务 | 验收 |
| --- | --- | --- |
| P0 | API 契约梳理 | 明确认证、请求体、响应体、错误码、分页参数 |
| P0 | SSE 协议固化 | `step`、`analysis_metadata`、`message`、`done`、`error` 字段稳定 |
| P0 | 数据口径统一 | 指标 API 与聊天分析结果使用同一计算口径 |
| P1 | `ChatService` 职责拆分 | 编排、模型调用、规则分析、SSE 输出边界清晰 |
| P1 | 错误处理标准化 | 导入失败、模型失败、鉴权失败、数据缺失有统一响应 |
| P1 | 生产配置清单 | 明确 dev/test/prod 差异和必需环境变量 |
| P2 | 持久化会话记忆 | 视业务需求决定是否引入数据库存储 |
| P2 | 提示词版本治理 | 记录 prompt 版本、模型参数和输出保护策略 |

## 验收标准

* 后端改造任务必须运行 `mvn "-Dfrontend.skip=true" pmd:check`。
* 后端改造任务必须运行相关 JUnit；核心改造应运行 `mvn "-Dfrontend.skip=true" test`。
* API 变化必须同步 OpenAPI 或相应文档。
* 涉及指标计算必须补规则引擎和准确率题库相关回归。

## 暂不做

* 不在本阶段直接引入完整账号系统。
* 不默认替换 Spring AI。
* 不默认引入微服务拆分。
* 不在没有真实数据源决策前设计复杂 ETL 平台。

## 开放问题

* 真实项目的鉴权是对接企业 SSO，还是先实现简单账号体系？
* 外部模型调用由后端统一托管，还是继续允许前端传入临时模型配置？
* 规则分析引擎是否需要作为独立领域模块从聊天编排中拆出？
* 数据查询 API 是否对外开放，还是只作为内部工具和前端服务接口？
