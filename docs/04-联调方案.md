# 联调方案

## 目标

定义前端、后端、数据库、模型服务和测试数据之间的联调方式，覆盖真实用户登录、opaque access/refresh 会话、RBAC、数据导入和 SSE。

## 本地启动

后端 PowerShell：

```powershell
cd backend
$env:APP_AUTH_BOOTSTRAP_USERNAME="admin"
$env:APP_AUTH_BOOTSTRAP_PASSWORD="temporary-password"
$env:APP_AUTH_BOOTSTRAP_DISPLAY_NAME="Local Administrator"
mvn "-Dfrontend.skip=true" spring-boot:run
```

前端：

```bash
cd frontend
npm ci
npm run dev
```

后端默认监听 `http://localhost:8081`；前端默认监听 `http://localhost:5173`，Vite 将 `/api` 代理到后端。

## 关键配置

| 变量 | 用途 | 当前要求 |
| --- | --- | --- |
| `APP_AUTH_BOOTSTRAP_USERNAME` | 空用户库初始化管理员用户名 | 首次本地/生产部署配置 |
| `APP_AUTH_BOOTSTRAP_PASSWORD` | 初始化管理员临时密码 | 至少 12 位；仅空用户库使用 |
| `APP_AUTH_BOOTSTRAP_REQUIRED` | 空用户库缺少凭据时是否启动失败 | demo 默认 false，prod true |
| `APP_AUTH_ACCESS_TOKEN_TTL` | opaque access token TTL | 默认 30 分钟 |
| `APP_AUTH_REFRESH_TOKEN_TTL` | refresh token TTL | 默认 7 天 |
| `APP_AUTH_COOKIE_SECURE` | refresh Cookie 是否仅 HTTPS | demo false，prod true |
| `APP_CORS_ALLOWED_ORIGINS` | CORS/refresh Origin 可信来源 | 默认允许 Vite 本地地址 |
| `APP_EXCEL_PATH` | Excel 数据源 | 默认 classpath 样例 |
| `APP_EXCEL_FALLBACK_ENABLED` | 工作簿失败时是否回退样例 | demo true，prod false |
| `APP_MODEL_BASE_URL` / `APP_MODEL_API_KEY` / `APP_MODEL_NAME` | 默认模型连接 | 可选 |

## 联调场景

### 1. 身份与会话

| 步骤 | 期望 |
| --- | --- |
| 首次启动空用户库 | 幂等创建 `ADMIN`、`ANALYST`、`VIEWER` 和一个临时密码管理员 |
| 用户名/密码登录 | `POST /api/auth/login` 返回一次性 access token；响应设置 HttpOnly refresh Cookie |
| 临时密码登录 | `/api/auth/me` 可用；业务 API 返回 403；只允许改密和退出 |
| 修改密码 | 撤销全部旧会话，要求用新密码重新登录 |
| 页面刷新或 access 过期 | 前端用 refresh Cookie 恢复；并发 401 共享一个 refresh 请求 |
| refresh 轮换 | 新 Cookie 生效；复用旧 Cookie 返回 401 并撤销整个会话族 |
| 退出/停用/重置密码 | access 过期时仍可通过受 Origin 保护的 refresh Cookie 退出；相关会话在下一次请求立即失效 |

### 2. RBAC

| 能力 | 权限 |
| --- | --- |
| 用户/角色管理 | `USER_READ`、`USER_MANAGE`、`ROLE_READ`、`ROLE_MANAGE` |
| 组织管理 | `ORGANIZATION_READ`、`ORGANIZATION_MANAGE`、`ORGANIZATION_GRANT_MANAGE` |
| Dashboard / 数据 | `DASHBOARD_READ`、`DATA_READ` |
| Chat / Agent 数据工具 | `CHAT_USE`，工具另检 `DATA_READ`、`KNOWLEDGE_QUERY` 或 `REPORT_GENERATE` |
| 报告 | `REPORT_READ`、`REPORT_GENERATE` |
| 模型连接测试 | `MODEL_CONFIG_TEST` |

管理联调应验证：未知权限键/角色被拒绝、预置角色不能修改、空角色被拒绝、最后一个有效管理员不能停用或失去管理能力；组织环、跨根挂载、未知/禁用节点和重复 grant 被稳定拒绝。

### 3. 数据与 SSE

| 场景 | 期望 |
| --- | --- |
| 工作簿可用 | `/api/data-status` 显示非 fallback |
| demo 工作簿不可用 | 使用内置样例并在前端提示 |
| prod 导入或数据库失败 | 启动失败，不回退 H2/样例 |
| SSE `step` / `analysis_metadata` / `message` / `done` | 顺序稳定，权限拒绝不会启动业务流 |
| SSE `error` | 前端解除发送状态并允许恢复 |
| 组织数据范围 | 同集团不同区域、同区域不同门店、多 grant 合并与 `includeDescendants=false` 的 HTTP/SSE/Agent/报告结果一致 |
| 伪造筛选参数 | 传入范围外 `dealerCode` 或组织参数返回空集/拒绝，不得扩大服务端 grant |

## 故障定位

| 现象 | 优先检查 |
| --- | --- |
| 首次生产启动失败 | bootstrap 用户名/密码是否完整，用户表是否为空 |
| 登录持续 401/429 | 用户状态、密码、用户名+来源限流 |
| refresh 403 | `Origin` 是否在 `APP_CORS_ALLOWED_ORIGINS` |
| refresh 401 | Cookie 是否过期/轮换/重放，会话族是否已撤销 |
| 业务 API 403 | `/api/auth/me` 的权限键和 `mustChangePassword` |
| 数据范围 403/空集 | 用户/角色是否存在启用组织 grant、映射节点是否启用、经销商是否已映射 |
| 数据接口 401 | access token 是否过期、账号/角色/密码是否刚变更 |
| 聊天工具被拒绝 | `CHAT_USE` 只允许进入 Chat；具体工具仍需要对应数据/知识/报告权限 |
| 模型测试失败 | `MODEL_CONFIG_TEST`、Base URL、host allowlist、API key、模型名 |

## 发布与回滚

生产先备份数据库，再依次应用 Flyway `V4__create_auth_identity_schema.sql` 与 `V5__create_organization_scope_schema.sql`。首次空库部署必须通过安全渠道注入初始化管理员临时密码；创建后应立即改密并移除环境中的临时值。V5 会创建 `GLOBAL_ROOT`，启动初始化只给预置 `ADMIN` 角色根节点后代 grant，并按 active batch 建立组织/经销商映射；普通存量用户必须显式授权。迁移是前向变更，不修改已应用 SQL。若应用版本需要回滚，保留新表和迁移历史，回滚应用二进制并停止写入新的身份或组织数据；不得恢复旧共享密钥入口。
