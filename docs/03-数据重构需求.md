# 数据重构需求

## 目标

明确从 POC Excel 样例数据走向真实项目数据体系需要补齐的内容。数据文档优先定义数据源、实体、字段、缺失值、质量报告、指标口径和迁移方向，避免后续 AI 或前端在不稳定数据口径上扩展。

## 当前数据源

当前有两份同结构样例工作簿：

* `mockservice/SampleData/Sample Data - 星曜汽车.xlsx`
* `backend/src/main/resources/Sample Data.xlsx`

启动时后端默认从 classpath 工作簿导入。demo 模式允许回退到内置样例数据，`prod` 配置关闭回退。

## 当前业务实体

| Entity | 主要字段 | 当前用途 |
| --- | --- | --- |
| `Dealer` | dealerCode、dealerName、city、dealerGroupName | 经销商主数据和范围匹配 |
| `Target` | dealer、productModel、year/month、asKTarget、opportunityWonCount、opportunityCreateCount | 目标达成和活动/目标对比 |
| `Opportunity` | dealer、productModel、purchaseHorizon、stageName、leadSource、createdDate、expectedCloseDate、probability | 商机漏斗、转化、购车周期、战败分析 |
| `Lead` | dealer、leadSource、stageName、productModel、createdDate、converted | 线索来源和转化 |
| `Task` | dealer、opportunityId、subject、status、createdDate | 销售跟进和任务积压 |
| `Campaign` | campaign、dealer、productModel、eventType、campaignType、目标/实际计数、createdDate | 活动效果和产出比 |

## 当前口径

* 默认开发/测试使用 H2 内存数据库，Hibernate `ddl-auto: update` 自动建表。
* `prod` 使用 PostgreSQL，Flyway 迁移脚本创建和升级 schema，Hibernate 只执行 `ddl-auto: validate`。
* 数据由 `ExcelImportService` 启动导入。
* 缺失的可选日期或目标分母保留为 `null`，不伪造为 `0` 或推断日期。
* 目标/活动达成率使用可比样本计算，观察总量和可比样本分子/分母需要分开展示。
* 缺失必要业务标识的行会被跳过并计入质量报告。
* `GET /api/data-status` 暴露导入来源、回退状态和质量汇总。

## 真实项目目标

### 数据源

* 明确真实来源：CRM、DMS、CDP、BI 报表、数据仓库或定期文件。
* 明确同步方式：API 拉取、消息、数据库视图、文件导入或手工上传。
* 明确刷新频率：实时、小时级、日级或月度。
* 明确数据负责人和字段口径负责人。

### 存储与迁移

* 从 H2 内存库迁移到持久化数据库。
* 引入迁移工具，记录 schema 版本。
* 建立 dev/test/prod 数据隔离。
* 明确是否保留 Excel 导入作为本地 demo 或兜底工具。

### 字段和质量

* 建立字段映射表：源字段、目标字段、类型、是否必填、缺失处理、业务说明。
* 建立数据质量报告：缺失、跳过、规范化、异常值、回退状态。
* 区分真实零值、缺失值、未知分类、未分配分类。
* 对所有 KPI 写明分母、分子、过滤条件和时间窗口。

### 权限和合规

* 明确经销商、区域、集团层级的数据可见范围。
* 确认是否包含个人信息或敏感业务信息。
* 建立审计和脱敏策略。

## 待拆任务

| 优先级 | 任务 | 验收 |
| --- | --- | --- |
| P0 | 真实数据源清单 | 每个业务域都有来源、刷新频率、负责人 |
| P0 | 字段映射表 | Excel/真实源字段到 Entity/API/指标字段可追踪 |
| P0 | KPI 口径表 | 六大分析场景的分子、分母、过滤条件明确 |
| P0 | 缺失值策略 | `null`、0、未知、未分配、跳过的规则明确 |
| P1 | 持久化数据库方案 | 选型、schema、迁移工具和环境隔离 |
| P1 | 导入质量报告扩展 | 质量问题可按 sheet、字段、原因追踪 |
| P1 | 主数据匹配策略 | 经销商 code/name/group/city 的匹配优先级明确 |
| P2 | 数据血缘和审计 | 分析结论能追溯到数据来源和版本 |

## 验收标准

* 任一 KPI 都能回答“分子是什么、分母是什么、哪些数据被排除”。
* 数据导入失败和样例回退必须对前端可见。
* 数据质量问题不能被模型润色隐藏。
* 真实数据接入前，不能删除可复现样例和准确率题库。

## 暂不做

* 不在本阶段直接建设完整数据平台。
* 不默认接入真实 CRM/DMS。
* 不在没有数据源确认前重写所有实体。

## 开放问题

* 真实项目是否必须保留 Excel 上传/导入能力？
* 经销商主数据以哪个系统为准？
* 分析口径按自然月、财务月、活动周期还是自定义时间窗口？
* 是否需要用户级或门店级的数据权限过滤？
* 准确率题库是否应该从样例数据自动生成一部分标准答案？
